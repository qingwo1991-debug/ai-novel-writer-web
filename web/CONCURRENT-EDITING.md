# 并发编辑与防覆盖边界

本应用是共享作者书库，不是多人实时协作编辑器。当前安全策略为 **同一作品单个浏览器编辑会话 + 服务器正文比较后提交**，绝不以“最后到达的请求”作为覆盖权限。

## 同一作品、多端

- 每个浏览器标签具有独立随机客户端身份；同一作品的另一个活动会话打开时返回 `409 PROJECT_OPEN_IN_ANOTHER_TAB`，不静默抢占。
- 同一个标签刷新重连保留既有客户端 sink/项目租约，不因为刷新而取消在途生成。
- 页面离开只发送经过 cookie/CSRF 校验的提示；断开、宽限和在途请求都由服务器判断后释放。活跃流/请求不因离开提示而被盲目取消。
- 不同作品可独立打开编辑。这不等于不同登录用户拥有独立私有书库。

## 普通正文保存

`db:draft-update-content` 必须提交上次确认持久化的 `expectedContent`。服务器在 SQLite **IMMEDIATE 事务**内检查：

1. 仍属于当前有效项目会话；
2. 当前草稿状态为可编辑工作稿；
3. 服务器完整正文与 `expectedContent` 精确相等（不 trim、不做 Unicode 规范化）；
4. 比较通过后一起更新正文与字数，失败则整体回滚。

缺少基线、过期正文或只读状态返回 `DRAFT_CONTENT_CONFLICT`。客户端不清除 dirty、不替换当前文字、不假报保存成功；提示先复制备份，再重新打开比较。保存期间的新输入仍保留为未保存内容；同一编辑视图不并行发起多个保存。

正文 CAS 比较的是内容而非单调修订号：若服务器正文变更后又精确恢复原文，旧基线仍可提交。这避免内容覆盖损失，但不声称检测每一次历史事件。

## AI 修稿与合并

- 修稿候选冻结来源草稿身份、状态和正文；生成出来的候选不自动成为当前正文。
- 显式合并在事务内核对当前目标正文、候选冻结来源及状态。来源变更时拒绝合并，候选保留。
- 有未保存人工编辑时不能直接打开/套用过期修稿；异步读取和完成事件还会核对当前标签内容代次，避免清除后续输入。
- 冲突不执行自动三方合并；由作者比较、选择或重新生成。

## 定稿

手动定稿冻结可见正文和标签的已保存基线，批量定稿使用原先已持久化的工作稿正文作为基线。服务器在同一 IMMEDIATE 事务内核对基线与可编辑状态，通过后才更新正文、定稿状态和 outbox。过期/缺失基线拒绝且不发布实体稿。已提交的完全相同冻结请求先走幂等返回，响应丢失重试不产生第二份定稿。

## 限制与验证

- 未保存文字目前保存在打开的编辑标签状态中；**不承诺断电、强制关闭、页面刷新后的未保存内容持久恢复**。发生冲突应先复制备份，不要直接刷新。
- 当前没有章节正文自动保存计时器的验收证据；以显式保存反馈为准。
- 不是 CRDT/OT、多光标或自动合并协作；若以后允许多个端同时可写，必须保留服务端 CAS，并加入版本分叉与显式合并界面，而不能移除锁后直接上线。
- `web/domain-tests.config.mjs` 的 113 项关键确定性回归覆盖普通保存竞争、缺基线、Unicode/空正文、只读、事务回滚、修稿来源/目标失效、定稿冲突/幂等和完成事件保留新输入。镜像的干净构建现在必须运行这组回归。
- 另有 74 项 Node 原生安全/传输/书库隐藏回归；实际浏览器的创建/隐藏刷新/重新打开/第二端占用/同标签租约验证见 [LIBRARY-CONFLICT-ACCEPTANCE.md](LIBRARY-CONFLICT-ACCEPTANCE.md)。真实付费生成竞争未在本轮重放。正文 HTTP 同基线竞争/过期租约/定稿竞争 7 项见 [DRAFT-CONFLICT-ACCEPTANCE.md](DRAFT-CONFLICT-ACCEPTANCE.md)；真实 CodeMirror 的输入、撤销重做、显式保存刷新及延迟成功响应保留后续输入见 [EDITOR-WRITE-CONFLICT-ACCEPTANCE.md](EDITOR-WRITE-CONFLICT-ACCEPTANCE.md)。
- 扩大运行的 22 个其他后端套件中 20 个通过、2 个失败（667 passed / 45 failed / 5 todo）；两个代表性失败使用原 HEAD 测试副本也能复现，但未据此宣称全部失败均已证实为既存问题。关键防覆盖测试全绿不等于项目完整测试套件全绿。
