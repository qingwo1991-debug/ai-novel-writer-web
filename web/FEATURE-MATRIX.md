# Full native Web feature matrix — implementation and acceptance status

## Scope, evidence, and status

**Target: the full AI-Novel-Writer product in a native browser + Node service, not a lite edition.** No Electron runtime, Xvfb, VNC, remote desktop, fake BrowserWindow, or desktop process hidden behind HTTP. Preserve the existing domain/data/workflow semantics; replace desktop capabilities with real Web interactions. Desktop window/install actions are replaced, not silently reported as successful.

Source anchor: repository `59153ceb`, package `1.4.0`, plus the changing native-Web working tree. The Node gateway/workers, neutral platform/renderer adapters, browser dialogs and reused application/domain services are implemented. This matrix now records **bounded evidence, not full product acceptance**. `ARCHITECTURE.md`, `PLATFORM-CONTRACT.md` and `WORKFLOW-LIFECYCLE.md` define boundaries; merely documenting a boundary does not pass its acceptance test. Evidence below predates any later candidate rebuild unless explicitly updated.

- **IMPLEMENTED (source-wired)** means an actual domain/UI/transport implementation is present and registered, not that every feature action has been exercised in a browser. **DOMAIN REGRESSION** is deterministic domain/controller evidence only.
- **API VERIFIED / UI VERIFIED (bounded)** credit only the operations or browser actions named in the evidence register. **PARTIAL / PENDING acceptance** leaves the other requirements open. No family below is declared fully accepted.
- **LIVE UNVERIFIED** means the integration exists but its real external service has not been configured/exercised; it does not mean the feature is unimplemented. A failed strict workflow is not a passing live test.
- Named `WEB-*` tests remain required acceptance scenarios, not assertions that those named tests have all been executed. Historical documentation reviews inspected source/artifacts and the operation JSON without rerunning tests. Subsequent parent/agent execution is attributed to exact runs/images below; updating this matrix is not itself evidence of a rerun.
- Source paths are relative to the repository root. Operation prefixes are inventory shorthand, **never authorization wildcards**. All 32 families F01–F32 and domain row D00 retain their responsibilities and acceptance plans.
- Deployment is one shared-author library/global configuration behind authenticated proxy access, **not multi-tenant isolation**. Cross-project/tab/lease and foreign-session grant protections do not create separate user-owned libraries.
- `web/operations.json` currently has **281 allowed routing entries (217 project, 42 global, 22 flexible) + 13 excluded = 294 classified names**. This includes project-scoped `review-revision:read-recovery` and `kb:import-finalized-text`. The excluded names are four desktop window actions, six updater actions, two smoke hooks and `mcp:get-config-path`. Static counts are not runtime authorization or full parity evidence.
- Workflows remain browser-orchestrated: **keep the tab open while running**. Individual generation/effects and recovery receipts are durable; automatic continuation of the entire workflow after tab loss is not implemented or promised. The per-run in-flight fence is not a cross-root resource scheduler.
